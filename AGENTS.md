# Puzzlet: working rules

A calm jigsaw puzzle game for ages 3 to 5. One child, one picture, pieces
that click home. Native Android, paid once, fully offline: no ads, no
trackers, no accounts, no network. Open source under MIT.

## This file is not the final word

These rules are the current best understanding, not the ceiling. If a change
you believe in contradicts one, do not silently drop the idea and do not
implement against the rule either: name the conflict, make the case, and let
the owner decide. An overridden rule is updated here, never left as a dead
letter.

Every session starts with two acts, in this order: read this file, then
`git fetch` and pull whatever is new on `main`. The owner works from more
than one machine; never build on a stale head.

## Hard constraints (non-negotiable)

1. **No music.** When sound arrives (M2), effects are synthesized,
   deterministic, and inharmonic, regenerated by `:tools` from code; a single
   pitched chime at most, never twice inside 1200 ms, because two pitched
   notes in sequence make an interval and intervals are where melody starts.
2. **No depiction of animate beings.** No humans, animals, faces, mascots,
   characters, or eyes-on-objects, in the app, the launcher icon, or store
   art. Only inanimate subjects: vehicles, houses, boats, planes, trees,
   flowers, fruit, sky, sun, moon, stars, geometric patterns.
3. **Zero manifest permissions.** This underpins the Data-safety declaration
   and the Families listing. No `INTERNET`, no exceptions. Do not add one
   without the owner signing off in this file first.
4. **English only.** No localization infrastructure, no translated resources,
   until the owner asks. Strings live in `res/values/strings.xml`, nowhere
   else.
5. **Nothing may feel like AI slop.** No placeholder copy, no dead buttons,
   no lorem text, no generic purple-gradient Material defaults, no stock
   iconography, no filler screens. Every string is a real sentence, every
   color is chosen, every asset is drawn for this app. A missing piece is
   listed below as a known gap, never faked.
6. **The app must not crash.** Defensive code, no `!!`, no unchecked casts,
   state that survives rotation and backgrounding, and tests around every
   rule. A Play-vitals crash is a stop-the-line event.

## Style

**No em-dashes, ever, unless absolutely necessary.** Not in chat replies,
release notes, commit messages, code comments, or this file. Use commas,
colons, parentheses, or a sentence break instead.

**Plain-text store text.** Release notes are pasted into Play Console, where
quotes, markdown fences, and dashes mangle or get auto-corrected: plain
prose, no quote marks around phrases, no markdown, no em-dashes.

## Shipping constraints

- `applicationId` is permanently `app.puzzlet`. Play ties an app to its
  first package ID forever. The code namespace mirrors it.
- `versionCode` only ever increases, from 1. `versionName` starts at 0.1;
  1.0 is the first store release, named here when it ships.
- `targetSdk` moves only together with an AGP that supports it.
- The signing keystore lives outside the repo and will live in the
  `KEYSTORE_BASE64` GitHub secret once created. If it is lost the app can
  never be updated again. M0 has no keystore; CI builds unsigned.
- Paid once on Play Console (owner handles the merchant profile and the
  upload). No billing SDK in the app, ever.

## The game

M0 is a brand screen by design: the mark, the name, the promise, nothing
that pretends to play. The M1 target it must grow into without a rewrite:

Scatter, drag, snap, celebrate. Pieces rest around a board; the child drags
each to its place; it clicks home with a spring, a soft thock, and a haptic
tick. No timer, no score, no fail state, no reading required. A peek button
shows a faint ghost of the picture; a stuck child gets a gentle highlight,
never a correction. Finishing holds the artwork up proudly, with confetti.

Difficulty lives inside each picture (roughly 4, 6, 9, 12, 16, 20, 24
pieces), chosen with big picture buttons. Three stays chunky.

Known gaps (honest, not faked): gameplay (M1), sound (M2), store listing
art beyond the launcher icon (M3).

## Architecture

```
app/      Compose UI, theme, the brand screen (gameplay lands in M1)
tools/    offline asset generators: plain JVM Kotlin, Java2D, no libraries
```

`:tools:makeIcons` draws the launcher icon set from the design system;
`:tools:checkIcons` fails the build if the committed PNGs drift from a fresh
regeneration. The in-app brand mark reuses the committed foreground PNG, so
the icon has exactly one source of truth. New asset families follow the same
make/check pattern; nothing hand-edited survives without a generator.

M1 will split gameplay the house way: pure-Kotlin rules with zero Android
imports, a host that performs them, and Compose that only renders. That
split is premature for a brand screen and must not be faked early.

## Forbidden

1. No composable without a caller, no button without an action.
2. No user-facing string outside `res/values/strings.xml`.
3. No color literal in UI code; everything comes from `PuzzletColors`.
4. No `!!`, no unchecked casts, no swallowed exceptions.
5. No network code, no WebView, no third-party SDKs. AndroidX and Kotlin
   only; each new dependency is proposed here first.
6. No file over 400 lines, no function over 40. Split early.
7. **Never add a `Co-Authored-By` trailer or any AI attribution to a commit
   message.** GitHub credits trailers, which would put the tool in the
   repository's contributor list. One person writes this app and the history
   should say so.

## Design seeds (chosen, not defaulted)

- Lagoon teal `#0C7A64`: the toy-box lid. Calm, gender-neutral, legible on
  paper in sunlight, distinct from the candy reds of ad-driven kids apps.
- Warm paper `#FAF6EF`: the play surface. Easier on young eyes than pure
  white, flatters the teal, prints well in store screenshots.
- Honey accent arrives with gameplay (stars, confetti); it must not appear
  before there is something to celebrate.
- Display face: Baloo 2 (OFL, bundled, offline), ExtraBold for the name,
  Bold for headings. Body text follows the system font under a 1.3 cap, the
  house rule: past that cap words stop fitting fixed play surfaces.
- Corners are generous (28dp large); nothing sharp touches a child's game.

## Build

```
./gradlew :app:testReleaseUnitTest :app:lintRelease   # unit tests, full lint
./gradlew :tools:checkIcons                           # committed icons match regeneration
./gradlew :app:assembleRelease                        # R8 release (unsigned until the keystore exists)
./gradlew :tools:makeIcons                            # regenerate the icon set after a deliberate design change
```

An Android SDK and the Android Studio JBR are installed on the owner's
machine (`JAVA_HOME` must point at the JBR; it is not on PATH). CI is the
loop: `build.yml` gates every push to `main` on tests, lint, generator
determinism (`:tools:test`) and a release build. `:tools:checkIcons` is the
local pinning gate: run it after any deliberate icon change and commit the
regenerated PNGs in the same commit. Do not pre-check UI on a local
emulator; add the screenshot capture workflow with M1 gameplay, pinned to
API 35, the same image the house uses. A push that touches no listed path
runs no CI at all; when a fix commit needs proof, dispatch manually
(`gh workflow run build.yml --ref main`).

## Commits and releasing

Small commits, plain messages, no AI trailers. Bump `versionCode` +1 with
every release-candidate change once the app plays; push to `main` and CI
does the rest. The owner uploads to Play Console. Release notes arrive in
chat as bare plain text that fits the 500-character Play field, counted
before handing them over, never assumed.

## Decision log

- D-001 (2026-09-04): Name is Puzzlet. One word, two syllables a 3-year-old
  can say, reads as a little puzzle, contains the store keyword, and has no
  colliding app, game, or brand on Play, the App Store, or GitHub.
- D-002 (2026-09-04): License is MIT, matching both house apps. Tradeoff
  accepted: anyone may compile a free clone; the moat is the listing, the
  brand, and the craft.
- D-003 (2026-09-04): English only. Revisit only on owner request.
- D-004 (2026-09-04): `applicationId` and namespace are `app.puzzlet`,
  clean, no legacy suffix. A new ID has no scars.
- D-005 (2026-09-04): Toolchain pinned to the house: Gradle 9.5.0, AGP
  9.3.0, Kotlin 2.2.10, Compose BOM 2026.08.00, Java 17, compile/target 37,
  minSdk 24. One house, one discipline.
- D-006 (2026-09-04): M0 dependencies are minimal on purpose: BOM,
  core-ktx, activity-compose, ui, foundation, material3, JUnit. Lifecycle
  and collections-immutable arrive with the M1 host and domain.
- D-007 (2026-09-04): M0 home is brand-only by design (see The game). A
  button that does nothing would be slop wearing a costume.
- D-008 (2026-09-04): Launcher icon is generated, never hand-drawn:
  teal tile, paper puzzle-piece glyph, white monochrome sibling, legacy
  PNGs for API 24-25. `checkIcons` pins them.
- D-009 (2026-09-04): The app owns the whole screen from day one
  (immersive bars, edge-to-edge). A child's toy-box has no chrome.
- D-010 (2026-09-04): `allowBackup` is false and cleartext is off, the
  house posture: there is nothing to back up yet and nothing to fetch ever.
- D-011 (2026-09-04): The toy-box is light-fixed: one warm paper world, no
  night variant, so launch never flashes dark before the first frame. A
  night scheme must earn its place with gameplay (M1).

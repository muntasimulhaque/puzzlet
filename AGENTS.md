# Puzzlet: working rules

A calm jigsaw puzzle game for ages 3 to 5. Sixteen inanimate pictures,
five counts, one child at a table. Native Android, paid once, fully
offline: no ads, no trackers, no accounts, no network, no permissions.
Open source under MIT.

This file is the always-loaded context: the working law, the hard
constraints, the map, and only what the code cannot say. Mechanics,
numbers, colors and copy live in the code. If a rule here and the code
disagree, the code is what ships and this file gets fixed.

## This file is not the final word

The rules are the current best understanding, not the ceiling. If a
change you believe in contradicts one, do not drop it silently and do
not implement against the rule either: name the conflict, make the case,
and let the owner decide. An overridden rule is updated here, never left
as a dead letter.

## Every session

1. Read this file.
2. `git fetch` and pull `main`: the owner works from more than one
   machine, and no session builds on a stale head.
3. Implement the request, then ask one question: anything else?
4. Hand off as things land, in chat, and only what changed: where the
   AAB is, where the fresh screenshots are, and the paste-ready release
   notes, short description and full description, each pasted only when
   its text changed. The owner reads the chat, not the diff; nothing
   lives only in a commit message or a file.
5. Session end: append a session entry to `docs/decisions.md`, bring
   README status and the submission guide current, and leave the tree
   clean.

## The change loop (owner's law)

The build waits for the owner's word. Nothing is cut, no `versionCode`
moves and no CI runs until the owner says the session is done; then one
build carries the whole session. A run of small tweaks must not burn a
`versionCode` each on work the owner may still change.

Commits are held with the build until the owner decides the cadence, per
change or one commit per session. That question is still open.

## Hard constraints (non-negotiable)

1. **No music.** Effects are synthesized, deterministic and inharmonic,
   regenerated by `:tools` from code. At most one pitched chime, never
   twice inside 1200 ms: two pitched notes in sequence make an interval,
   and intervals are where melody starts.
2. **No depiction of animate beings.** No humans, animals, faces,
   mascots, characters, or eyes on objects, in the app, the launcher
   icon, or store art. Only inanimate subjects.
3. **Zero manifest permissions.** This underpins the Data-safety
   declaration and the Families listing. No `INTERNET`, no exceptions.
   A new permission needs the owner's sign-off written here first.
   (androidx.core merges in one app-private, signature-scoped receiver
   permission; that is the library's doing, documented not fought.)
4. **English only.** No localization infrastructure and no translated
   resources until the owner asks. Strings live in
   `app/src/main/res/values/strings.xml`, nowhere else.
5. **Nothing may feel like AI slop.** No placeholder copy, dead buttons,
   lorem text, generic Material defaults, stock iconography, or filler
   screens. Every string is a real sentence, every color is chosen,
   every asset is drawn for this app. A missing piece is listed as a
   known gap, never faked.
6. **The app must not crash.** Defensive code, state that survives
   rotation, backgrounding and process death, tests around every rule.
   A Play-vitals crash is a stop-the-line event.

## Style

- No em-dashes, ever, unless truly necessary: not in chat, release
  notes, commit messages, code comments, or this file. Use commas,
  colons, parentheses, or a sentence break.
- Store text is plain prose. Play Console mangles quotes, markdown
  fences and dashes: no quote marks around phrases, no markdown.
- US English in notes and store text: color, favorite, behavior.

## Forbidden

1. No composable without a caller, no button without an action, no
   composable that takes a ViewModel.
2. No user-facing string outside `res/values/strings.xml`.
3. No color literal in UI code; everything comes from `PuzzletColors`
   (scene palettes are content constants beside their shapes).
4. No `!!`, no unchecked casts, no swallowed exceptions.
5. No network code, no WebView, no third-party SDKs. AndroidX and Kotlin
   only; each new dependency is proposed here first.
6. No file over 400 lines, no function over 40. Split early.
7. No `Co-Authored-By` trailer or any AI attribution in a commit
   message. One person writes this app and the history should say so.

## Shipping

- `applicationId` is permanently `io.github.muntasimulhaque.puzzlet`.
  Play ties an app to its first package ID forever; the code namespace
  mirrors it.
- The version walk: `versionCode` only ever increases and is never
  reused; `versionName` is `versionCode` divided by ten, one decimal.
  The live numbers are in `app/build.gradle.kts`.
- `targetSdk` moves only together with an AGP that supports it.
- The signing keystore lives outside the repo (owner vault), with its
  base64 twin in the `KEYSTORE_BASE64` GitHub secret and the passwords
  in three more secrets. If it is lost, the app can never be updated
  again. Local builds without it stay unsigned.
- Paid once on Play Console. No billing SDK in the app, ever.

## Releasing

Bump `versionCode` +1 and `versionName` by 0.1, push to `main`, and CI
signs and publishes the AAB and APK to the `latest-build` GitHub
release. Download the newest AAB into `play-store/aab/` (gitignored) and
keep it there until the owner submits it; after submission, delete it,
so a stale build can never be uploaded twice.

Release notes always arrive in chat, bare plain text, never a file
reference alone: ready to paste, under the 500-character Play field,
counted before handing over, and stored in the submission guide. Notes
never name the owner's email and carry no contact line. Store copy is
not release notes: the full description may end on the owner's contact
line.

The listing kit, the paste-ready listing and the console answers live in
`play-store/play-store-submission-guide.md`. The privacy policy is live
at `https://muntasimulhaque.github.io/puzzlet/privacy.html`.

Before a store release, rerun the goal audit against the original brief:
no music, no animate beings, no internet, no ads, no trackers, paid
once, native, open source, three form factors, Apple or Google polish,
and a game that makes the child think. Human eyes judge the mark and the
captures before upload; the owner judges every design.

## Build

```sh
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"   # not on PATH
./gradlew :core:test :app:testReleaseUnitTest :app:lintRelease   # tests, full lint
./gradlew :tools:test :tools:checkIcons :tools:checkSounds       # asset pins
./gradlew :app:assembleRelease                                   # R8 release, signed when the keystore is present
./gradlew :tools:makeIcons :tools:makeSounds :tools:makeArt      # regenerate art, deliberate changes only
./gradlew :tools:makeScenes :tools:makeCut :tools:makeWashes     # review sheets into build/, never committed
```

`app/src/androidTest` holds the screenshot harness; captures are
reviewed from CI, never pre-checked on a local emulator. `.github/`
workflows are the CI truth. A push touching none of a workflow's paths
runs neither workflow, so dispatch a fix build manually
(`gh workflow run build.yml --ref main`) when a commit needs proof. A
version bump also triggers the capture run
(`app/build.gradle.kts` is in its paths), so every release pays for one.

## The game (intent, not mechanics)

Mechanics, counts and layout math live in `core/` and are pinned by
tests. What must stay true and is not visible in any one file:

- No timer, no score, no fail state, no reading required, no tutorial.
  The tray-and-board layout is the whole lesson; a teach-me demo was
  vetoed.
- The board is blank like a real table: no picture, no slot glow, ever.
  The finished picture lives behind one top bar coin (peek).
- The child picks the count by look in the cut chooser; a parent pick
  outranks the ladder and stays put.
- Pieces wait in a tray on one even grid, lift on first touch, and click
  home near their place. A miss glides back; no piece starts within snap
  tolerance of its slot, and there is no mid game restart. The shelf
  takes the axis the field can spare: above a tall field, beside a wide
  one.
- Every picture stands on a graded ground, so no piece is ever blank.
- Finishing holds the completed picture for one quiet second before the
  plate rises with confetti, Again leading.
- Wins, chosen counts and the sound switch persist; the switch silences
  sound only, never haptics. Unfinished games do not persist: every
  launch starts fresh on the shelf.

## Map

```
core/                      pure Kotlin, zero Android imports (JVM module):
  PieceCut.kt              the measured die-cut edge
  Puzzle.kt                game state: deal, grab, drop, win
  Layout.kt                tray grid, board side, seats
  Ladder.kt                counts, wins walk, openingCountFor (one truth)
  Scene*.kt                scene data, grounds, clues, washes
app/src/main/.../host/     PuzzleHost, PuzzleStore, SoundBoard
app/src/main/.../ui/       Compose screens; SceneRaster.kt is the one
                           bitmap cache, for still pictures only
app/src/main/res/values/   strings.xml: every user-facing string
tools/                     offline generators; MarkPiece.kt is the
                           mark's one home; checkIcons/checkSounds pin
                           the committed bytes
docs/                      privacy.html, OFL-Baloo2.txt, decisions.md
play-store/                listing kit, screenshots per form factor, aab/
```

- Tests are the laws: `LadderTest`, `PieceProfileTest`,
  `SceneCoverageTest` (no blank piece), `SceneWashTest`,
  `PuzzleTrayTest`, `SceneNameFitTest`.
- Adding a picture: one builder, `Scenes.all`, `strings.xml`,
  `sceneNameRes`, then pass the coverage test; captures and listing text
  follow.
- Code comments cite decision numbers (D-nnn). Those resolve in
  `docs/decisions.md`, which is history, not rules.

## Glossary

- **shelf**: the home screen of picture cards.
- **tray**: the shelf holding unplaced pieces, above the board on a tall
  field or beside it on a wide one.
- **board**: the blank play surface; a real table, no picture on it.
- **cut**: the piece geometry for a count. As a verb, cut a release
  means bump the version and push. Context separates the two.
- **count**: a piece count, one of 4, 6, 9, 12, 16.
- **seat**: a piece's resting place in the tray. The jumble shuffles
  seats per deal; the cut stays stable.
- **ladder**: the wins walk 4 to 6 to 9; it stops at 9.
- **wins**: per-picture completed-game counts in DataStore.
- **opening count**: the one truth for where a picture opens
  (`openingCountFor`).
- **chooser**: the bottom plate of five real-cut tiles.
- **peek**: the coin that holds the finished picture up on a scrim.
- **mark**: the launcher and store art; one home in `tools/MarkPiece.kt`.
- **wash**: the peek coin's on-state tint from the scene's own accent
  (`core/SceneWash.kt`).

## Design

- Palette and type live in the theme (`PuzzletColors`, Baloo 2). The
  world is light-fixed: one warm paper world, no night variant. Corners
  are generous; nothing sharp touches a child's game.
- Motion lives in `ui/Motion.kt`: one arrival, one lift, one settle. A new
  animation uses those numbers or adds its own there, never ad hoc.
- The mark is one real die-cut piece carrying the sailboat, generated by
  `:tools:makeIcons` and pinned by `checkIcons`, never hand-edited. The
  banner: brand teal, paper type, mark left, name right, nothing behind
  the name.
- Every asset is drawn by `:tools` from code. Never fix a pixel by hand.
- For every design round, render takes as images in one folder and let
  the owner point at one. Do not describe takes in prose and hope.

## Lessons that still bite

- `gradlew` needs the POSIX executable bit in the index
  (`git update-index --chmod=+x gradlew`); a Windows checkout once
  committed it as 100644 and CI died on Permission denied.
- Icon bytes pin across JDKs only for flat fills of plain paths. Wide
  strokes and `Area` booleans rasterize differently on CI's Temurin than
  on the local JBR, so grooves are filled paths; strokes and booleans
  are out.
- Do not draw a jigsaw piece from memory. Two hand-drawn rounds were
  bounced. Fetch a real reference, crop it, measure it, then draw.
- Colors are not distinct until they are measured: two yellows in the
  mark looked fine and sat 12 deltaE apart.
- Scene math stays in Double end to end, converting to Float only at the
  draw call. Map piece-unit coordinates through the piece's span and
  offset before probing pixels.
- Still surfaces composite one raster (`ui/SceneRaster.kt`); the play
  field stays pure vectors. A tile that draws outside its layout bounds
  loses that overdraw offscreen, so layer caching for play tiles is out
  until the shadow fits inside.
- Measure frame phases (UI, sync, GPU) with gfxinfo framestats, not just
  the jank percentage: they name which side of the frame is heavy. The
  emulator is a measuring tool, never a design judge.
- When an elvis chain reports a nonsense common type (`Any`), check the
  two operand types first. Kotlin's `Path.readBytes` lives in
  `kotlin.io.path`, not on `java.nio.file.Path`.
- The engine's guard (`closeAndCheck`) has already caught a real
  assembly bug before any human saw a crooked piece; guards like it stay.
